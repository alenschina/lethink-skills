# 动态组件排查指南

先区分“完全没有请求”“请求失败”“成功但空列表”和“有数据但未渲染”，不要看到空白页面就修改接口或表。以下运行时细节应与用户部署版本核对。

表单提交组件先阅读 [表单说明](configured-lead-form.md)：使用登录同款点选验证码时，请求是 `auth/clickCaptcha`、`auth/checkClickCaptcha` 和 `CustomerLead/configuredSubmit`，没有 execute 请求不等于故障；使用现有留资管理，不适用下面的列表分类和内容菜单规则。

## 列表完全没有请求

1. 检查站点页面或预览 iframe 的 Network，按 `execute` 筛选并重新加载。标准路径可能适配成 `/cmsapi2`；组件库纯静态预览不一定请求接口。
2. 读取 Elements 中最终的 `data-lethink-dynamic`，检查 JSON 语法。源码通过不代表页面实例合并后的配置通过。在正确 iframe 的 Console 中，选中组件根节点后可用 `JSON.parse($0.getAttribute('data-lethink-dynamic'))` 检查；若属性保留实体，还需按运行时的实体解码逻辑核对。
3. 检查共享运行时是否加载并调用 `boot`、`list.path` 是否非空且已替换变量、当前 `site_id` 是否可解析。没有站点上下文会进入默认数据预览分支。
4. 检查 `static_preview`、`static_data_only`、`preview_mode: "static"` 或启动钩子的预览模式。
5. 有 `category` 段时，查看是否只发了分类请求。分类为空或失败可能使列表请求不再执行。

已确认案例：公示组件的 `params` 右花括号后漏逗号，`parseDynamicConfig` 返回 null，运行时跳过初始化；用户补正 JSON 并重新部署后恢复。这个错误与 `params` 的业务值或参数层级无关。当前 `RT.boot` 在解析前标记已启动，直接在 Elements 中补逗号后再次 boot 不一定生效，应保存并重新加载页面。

## 请求已经发出但失败

查看 HTTP 状态和响应 `code`、`message` / `msg`；核对接口是否存在且启用、当前绑定、站点上下文及访问权限。运行时可能把请求失败和空列表都显示为空状态，不能只看 UI 判断没有内容。

不要为了取到数据而复制相邻组件的推荐条件、改成 OR、换站点 ID 或修改公共接口。先确认失败发生在哪一层。

## 分类值为空或筛选没有生效

沿 [动态请求契约](dynamic-request-contract.md) 的两阶段合并规则核对：

- HTML 中 `{{$Var@category_id}}` 是否有同名 `unit_json` 顶层字段；若字段使用其他名字，应核对具体映射。
- 当前页面实例是否填写并保存真实分类 ID，是否仍保留旧配置。
- `data_source.params` 是否覆盖了 HTML 参数，最终指令和 Network 的值是否符合预期。
- 接口实际查询是否使用该参数，分类是否启用且有可展示内容。

公示组件的另一处已确认问题是配置项没有配对，导致 `category_id` 为空。空值会从查询参数中省略，表示不限定分类，本身不会阻止请求。`category_param: "category_id"` 只指定参数名，不会替用户选定“公示”分类。

### HTML 声明了分类参数，最终指令却没有这个键

另一次页面截图中，`list.params` 只剩平台补入的页面、组件等实例坐标，原先的 `category_id` 已消失。应区分“键不存在”和“键存在但值为空”，前者先查服务端合并，而不是接口过滤或浏览器的空值序列化。

容易触发该现象的写法是：

```json
"params": {
  "category_id": "{{$Var@news_category_id}}"
}
```

即使 `news_category_id` 字段存在且值正确，实例 `data_source.params` 若不含 `category_id`，整体替换后仍会把它移除。接下来的回填只查 `$props['category_id']`，不会追踪原变量表达式去读取 `$props['news_category_id']`。因此“变量引用已配对”不能单独证明请求参数会保留。

新组件可优先让请求参数、顶层字段及 HTML 变量都使用 `category_id`。修改已有字段名前先核对其下拉配置、内容入口及其他引用，保留需要的控件配置，并重新填写、保存当前实例的值。若必须保留 `news_category_id`，需由已验证的同步或映射逻辑写入 `data_source.params.category_id`；仅增加 `category_param` 无法建立这个映射。

校验器会在“数据源会覆盖 params、数据源缺少该参数、又无同名顶层字段”时发出丢失风险警告。它不把不同字段名本身判为 JSON 错误，也不代替最终页面验证。这里的规则仅适用于当前参数覆盖及同名回填链路。

搜索、翻页、日期变化后都应保留固定分类。总数和总页数应由后端针对相同筛选结果计算，不能前端只过滤当前页来冒充分页查询正确。

## 内容管理入口没有出现

按顺序检查：

1. 组件类型是否为动态组件。
2. 组件记录的标签是否包含精确的 `cat:*`，例如产品内容是 `cat:product`。
3. 页面是否已经保存。动态资源激活发生在组件挂载到页面并保存时。
4. `content_module`、`content_schema_key`、`content_path` 和编辑模块是否匹配真实内容模块。
5. 刷新后台、切换站点或重新登录，排除导航和权限缓存。
6. 如果页面实例保留了旧数据源配置，重新保存页面；必要时在测试页移除后重新添加组件。

`content_module: product` 不能替代 `cat:product`。固定内容入口的识别来自组件标签。

## 接口返回成功但页面不渲染

检查以下四个位置是否一致：

- 接口响应数组路径，例如 `data.list`。
- `data_source.item_field`。
- HTML 指令中的 `field`。
- HTML 的 `data-component-items`。

再检查 `mapping` 后的字段名是否和 `{{placeholder}}` 一致。树形分类接口返回扁平 `id`、`parent_id` 时，应使用 `category` 分支和 `parent_field`，根区域绑定 `categories`，子区域绑定运行时生成的 `children`。

查看浏览器实际网络请求。请求应使用 `/cmsapi/api.api/execute?path=<path>`，并携带当前站点上下文。不能只看接口在别的站点或接口调试页是否成功。

## 链接里的 ID 没有替换

不要继续堆叠字符串占位符。把链接声明放进 HTML 指令对应的数据分支：

```json
{
  "detail_url": "/products/product-list",
  "detail_id_key": "id",
  "detail_id_param": "category_id",
  "detail_link_field": "link"
}
```

映射中保留实际链接字段，HTML 改成 `href="{{link}}"`。当前运行时优先保留有效链接，缺失时按配置根据 `id` 生成完整链接，再执行模板填充，可避开 CMS 保存或解析 HTML 属性时破坏 `?category_id={{id}}` 的情况。默认详情路径须在目标站点验证。

## 怀疑跨站点串数据

分别在两个站点观察同一接口请求和响应：

1. 确认请求解析出的 `site_id` 不同。
2. 确认后端接口查询按 `site_id` 过滤。
3. 确认没有在 HTML、`params` 或缓存键中写死站点 ID。
4. 确认返回记录本身属于目标站点。

同一接口名和同一物理表不代表数据串站。接口定义的全局作用域或 `table_scope: shared` 也不能证明内容跨站共享。真正的数据范围由记录归属和实际查询决定；业务声称全站共享时，应明确验证是否存在共享数据源或特殊过滤规则，而非默认移除站点条件。

## 担心影响已有组件

按修改对象判断影响面：

| 修改对象 | 常见影响范围 |
| --- | --- |
| 新组件自己的 HTML、映射、`list_path` | 当前组件或其实例 |
| 某站点公共内容记录 | 该站点内所有读取这批内容的组件 |
| 公共 API 注册、后端实现 | 所有调用该接口的组件和站点 |
| 公共表结构 | 所有依赖该表的业务 |

`existing_api` 配置只是引用公共接口，不会因为新组件的映射写错而改写旧接口或旧表。但在内容中心编辑公共记录，影响的是共享数据消费者。

## create_package 结构改了但旧表没变

不要假定重新加载页面会迁移数据库。先确认：

- 页面是否重新保存并触发激活。
- 后端激活日志是否执行了结构同步。
- 物理表是否真的新增或修改了列。
- 接口返回是否包含新字段。

结构变更先在测试站点验证。若激活流程只负责首次创建而不负责迁移，需要后端迁移方案，不能靠刷新页面解决。
