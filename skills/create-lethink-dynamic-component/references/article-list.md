# 文章列表：新闻、公示等分类页面

当前项目中，新闻、公示属于同一文章模型，分类不同。使用 `existing_api` 复用 `article_list`，内部模块为 `news`、内容模型为 `article`、组件标签为 `cat:news`，常见维护入口为 `content/article` / `content/articleCategory`。字段和路由仍需从用户实际项目核对。

## 从静态稿开始

用户已提供 HTML 或路径时先读取；未提供且没有说明不存在时，询问是否有原始静态 markup。已有 CSS、JS、图片及页面结构优先沿用，只替换重复内容及所需交互绑定。没有静态稿则按需求生成；不用反复索要。

卡片里的展示日期、第三个“请选择”、七页页码等不能直接当成筛选定义。确认第三个控件代表日期还是业务分类，并让页数来自接口。不能仅凭画面推断数据表和共享规则。

## 参考文件

- [字段模板](existing-api-article-list-template.json)：固定分类、每页条数、详情页地址和预览样例。
- [HTML 模板](article-list-template.html)：列表模板、年/月/日、搜索、分页。
- [参考样式](article-list-template.css) 和 [键盘操作脚本](article-list-template.js)：没有现成稿时可作为起点；用户有静态稿时按其视觉结构改造。

这些文件由已实践的公示列表组件整理而来。保留 `news` 类名和内部模块不代表只允许新闻分类。样例标题和 ID 均为虚构预览数据，不能写成正式文章；正式页面无结果时显示空状态。

## 必须配置的值

1. 在目标内容源的文章分类管理中查到真实公示分类 ID，填写页面实例 `category_id`。HTML 使用 `{{$Var@category_id}}`，字段名称必须配对。模板默认留空并提示必填；空值不阻止请求，但会失去分类限制，不能作为公示页面验收。
2. 确认当前环境启用 `article_list`，列表角色绑定正确，不引用其他组件实例生成的接口。
3. 设置每页条数，默认 9；核对真实详情承载页。`/news` 只是模板已有的默认路径，不能假定每个站点都有该页面。

`table_scope: shared` 表达复用内容资源，不证明取消站点过滤。当前专用新闻查询存在 `a.site_id = $siteId` 条件；全站共享需要独立验证实际来源，不能通过不传 site_id 来推断。

## 数据和链接

预期响应为 `data.list`，使用 `id`、`title`、`summary`、`publish_time`、`link`，分页取 `data.pagination.pages`。`mapping.date = publish_time`；时间格式以实际接口返回为准。

链接优先保留接口已有的有效链接，缺失时由 `detail_*` 生成。若响应使用 `detail_url` 等其他字段，应核对字段和运行时映射顺序后调整，不能仅因接口名相同就假定契约相同。HTML 使用 `href="{{link}}"`，避免在 href 中拼接多个占位符。

## 固定分类、筛选与分页

固定公示分类不需要分类切换 UI，使用 `list.params.category_id`，不添加 `category` 段。详情及参数层级见 [动态请求契约](dynamic-request-contract.md)。

本参考场景要求分类、日期、关键词同时满足，因此使用 `params.filter_logic: and`；其他业务按需求决定。不要照抄首页推荐组件的 `is_recommend: 1`、`recommend_type: home`，也不要为了能取数就改为 OR。

当前后端 `ApiService::shouldUseProfileNewsListRuntime` 对 `article_list` 的 OR 或明确推荐条件有专用分派，进入 `SiteProfileService::newsListData`；AND 且没有推荐条件时可继续走通用或绑定查询。此细节应随项目版本复核，不作为所有部署的固定规则。两条链路的过滤、字段及分页均要以实际接口为准。

当前浏览器控件契约：

- 根节点 `data-lethink-page-size` 提供页大小，`data-lethink-enable-pagination="1"` 启用分页；`pagination.enabled` 不是当前浏览器开关。
- `list.search` 指向组件内搜索表单；由通用运行时发起查询，避免自写另一套 fetch。
- 日期控件使用 `.year-select` / `.month-select` / `.day-select`，含 `p`、隐藏 input、`ul`。年份及日期选项由运行时生成，参考脚本补充键盘操作。
- 当前运行时默认年份范围为当年及前七年，不能假定涵盖所有历史文章。日期应覆盖闰年和更改年份/月后下级条件清空。
- 搜索和筛选变化回到第一页；翻页保留分类、关键词和日期；清空输入后再提交才清除关键词。
- 总页数来自同一筛选条件下的后端分页，不能写死，也不能只过滤当前页的数据。
- CSS、JS 和选择器以组件根节点为范围，验证多个实例互不干扰。

## 后台与验收

新建动态组件，填入字段、HTML、CSS、JS，设置 `cat:news`。挂载测试页面并保存，配置真实分类 ID。更新已有组件时核对页面实例是否仍保存旧字段和数据源，再保存、重新加载。

依次核对：合法的最终指令 JSON、首屏 execute 请求、正确分类和站点值、标题及日期、真实详情链接、搜索与日期组合、翻页与清除条件、空结果、移动端及多实例行为。没有请求时先看 [排查指南](troubleshooting.md)，不直接修改公共接口。

## 验证边界

交付分别记录以下结果，不合并成一句“已验证”：

| 层次 | 能证明什么 |
| --- | --- |
| 字段与指令静态校验 | JSON、支持的变量及字段引用可解析 |
| 本地真实运行时与模拟响应 | 请求参数组装、模板渲染和交互行为 |
| 真实 CMS 页面和接口 | 保存与实例覆盖、实际数据范围、分类筛选、分页及详情可达性 |

公示组件实践已确认：缺逗号导致零请求；修正 JSON 并重新部署后恢复；空分类来自字段配置未配对。曾通过的本地模拟检查不应写成后续所有站点已验收。
