# 组件级表单运行时

当公共动态运行时没有 `cfg.form` 能力、需求只服务当前组件，并且用户明确允许新增组件 JS 时使用。默认交付仍是 `unit_json` 和动态 HTML；本参考描述第三项产物 `component.js` 的边界，不要求改写组件 CSS，也不把一次性实现扩散到公共源码。

## 先确定脚本归属

检查页面实际加载的公共动态运行时、组件原稿 JS 和依赖脚本。搜索 `configuredSubmit`、`clickCaptcha`、表单 `submit` 监听及自定义控件选择器：

- 公共运行时已经完整处理 `cfg.form` 时，不再添加组件脚本。
- 原稿 JS 已有真实提交逻辑时，先判断能否按现有协议复用；不要让两个监听器各发一次请求。
- 公共依赖已经处理省份等自定义下拉时，不录入再次绑定同一选择器的原稿 JS。一次点击展开后立即收起，通常是两份脚本重复绑定切换事件。
- 只有当前组件需要新增行为时，把实现写进组件 JS，公共 `lethink-dynamic-runtime.js` 保持原样。

组件级脚本是经过确认后的最小例外。交付时明确列出它替代或省略了哪段既有行为。

## 初始化边界

脚本应扫描当前文档中的 `[data-lethink-dynamic]`，解析最终属性值，只初始化存在对象型 `form` 配置的根节点。每个根节点设置实例级保护标志，重复执行脚本或页面再次扫描时不得重复绑定 `submit`。

所有表单、状态节点和自定义控件都相对组件根节点查询，不依赖全局唯一 `id`。同页存在多个组件实例时，各自保存发送状态、验证码挑战、提示和重置行为，不能互相覆盖。

上下文从 CMS 最终挂载结果读取：

- `component_id` 优先读取顶层 `params.component_id`。
- `site_id` 可按顺序读取配置值、`params`、页面 `meta[name="lethink-site-id"]`、已知页面全局值或查询参数。
- 两者必须是正整数；模板和脚本不写死开发时的组件、页面或站点编号。

缺少上下文、显式静态预览或编辑器预览时禁用真实验证码和提交，并给出可理解的状态提示。组件预览用于检查结构；真实交互要在测试站点的页面预览中完成。

## 表单与请求状态

表单提交时先执行浏览器原生校验，再按 `form.schema.fields` 读取和校验值。字段键必须与 HTML `name` 对齐。验证码独立于业务字段；在打开验证码前保存本次业务值，取消或失败时不重置表单。

用实例级 `sending` 状态阻止重复弹窗和并发 POST。请求流程仍遵循 [配置式留资表单](configured-lead-form.md) 中的三个接口。最终接口只有返回成功 envelope 且包含有效新记录 ID 时才算成功，随后才能清空表单和恢复自定义下拉初始文案；响应不明确时保留输入，提示用户先确认后台记录。

刷新或关闭验证码时增加挑战代次标识。异步响应返回后先比较代次和关闭状态，旧响应不得覆盖新挑战，也不得在弹窗关闭后继续提交。

## 点选验证码加载态

弹窗插入 DOM 后，验证码接口和 base64 图片解码都需要时间。不要先渲染空图片和空提示，再等待内容填充。推荐使用固定舞台：

1. 舞台宽度跟随弹窗，并使用服务端图片宽高比，例如 `aspect-ratio: 350 / 200`。
2. 初始只显示覆盖舞台的“正在加载验证码…”面板；图片容器和点选提示不可见。
3. 图片容器使用 `visibility: hidden` 保持在布局中。不要给待加载图片或父节点使用 `display: none`、HTML `hidden`，部分 CMS 预览环境会因此不触发 data URL 图片的 `load`，导致永久停在加载态。
4. 验证接口返回后先校验 `id`、提示数组、原图尺寸和 `data:image/...;base64,` 格式，再设置 `img.src`。
5. 只在图片触发 `load` 后隐藏加载面板、显示图片容器和“请依次点击”提示，并解除点选锁定。
6. `error` 时保留稳定舞台，显示加载失败及刷新入口。刷新从第 2 步重新开始。

点击坐标按实际显示区域换算回服务端返回的原图宽高。图片尚未完成加载、矩形尺寸为零或挑战已过期时不记录点位。

## CMS 同步

CMS 可能同时保存源组件资源和页面中的组件实例。修改组件 JS 后完成以下核对：

1. 更新源组件 JS。
2. 在已挂载的测试页面同步组件资源并重新保存、发布。
3. 若预览仍输出旧版本，按现有站点流程刷新预览缓存。
4. 在 Elements、页面响应或 Network 中检查实际脚本文本，而不是只看工作区文件。
5. 必要时比较源资源、页面实例和交付文件的长度或内容摘要，确认三者一致。

不要把开发环境分配的组件、页面、资源或站点 ID 写进可复用文档和脚本。

## 最小验证集

组件脚本至少验证这些行为：

- 页面初始化前不发请求；有效提交才打开一个验证码弹窗。
- 图片 `load` 前只有固定加载态，没有空图片或空提示；`load` 后图片尺寸有效且提示可见。
- 图片或接口失败后可以刷新；刷新和关闭后的旧响应被忽略。
- 取消不调用预检或最终提交，并保留业务输入。
- 预检失败和最终提交失败都保留输入；再次提交使用新挑战。
- 连续点击提交只产生一条请求链。
- 缺少站点/组件上下文和组件预览不发真实请求。
- 同页多个实例的挑战、状态和重置互不影响。
- 公共动态运行时不包含同一组件表单逻辑，避免重复处理。

自动化测试之外，在真实 CMS 页面检查加载态到图片的切换、刷新、取消、缩放点选、成功入库及留资管理展示。接口响应很快时，加载面板可能短到肉眼看不见；可通过测试控制图片 `load` 时机验证中间状态，不能只观察最终弹窗。
