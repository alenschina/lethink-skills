# 产品详情组件与后台数据接入

用于产品详情页中的应用场景、成功案例等子列表，以及对应的产品编辑 Tab。以下代码路径和 556 / 567 是当前项目的定位线索与已验证实例；接入其他版本时重新核对实际实现，不把组件编号或本次校验规则当作平台通用约束。

## 1. 先决定数据归属和复用影响

产品 Tab 是内容维护入口，组件是读取者。Tab 名称、组件标签、存储字段不是同一个概念；要沿着保存和读取代码判断绑定关系。

| 业务意图 | 数据设计 | 影响 |
| --- | --- | --- |
| 同一产品的同一份内容，换一种展示布局 | 复用原字段和 Tab | 修改内容会影响同一产品下所有读取该字段的组件；新增只读组件本身不修改数据 |
| 名称相似，但内容用途、维护责任或生命周期不同 | 新增语义明确的字段和 Tab | 分开维护；不自动复制或覆盖原字段 |
| 直接展示案例中心的标题、图片和描述 | 保存关联 ID，读取目标内容 | 案例中心更新会影响展示 |
| 手填展示内容，只从本站案例获取链接 | 手填字段与关联 ID 分开保存 | 目标选择只改变链接，不覆盖标题、图片和描述 |

先搜索字段的现有读写方、消费者和历史别名，说明共享后的影响。用户已经明确选择复用或独立时按其意图实现，无需再次确认。仅当语义仍不清楚时询问数据是否需要同步维护。

产品拥有的有序图片、标题数组可以保存在产品 `ext_json` 中，并通过 `existing_api` / `product_detail` 读取，不因为新增组件而生成私有表、接口或菜单。条目需要独立管理、查询、权限或跨产品复用时，再考虑内容中心关联或真实子模型。

本次最终契约：

- 556：原“应用场景”Tab → `ext_json.application_scenarios`，条目为 `image / title`，卡片无跳转。
- 567：“成功案例”Tab → `ext_json.success_cases`，独立手填展示内容并配置链接。

## 2. 一次对齐完整读写链路

按下列链路定位相邻实现，再修改必要部分：

`编辑草稿 → 提交序列化 → 后端字段白名单与校验 → ext_json / 文件引用 → 编辑回显 → product_detail 规范化输出 → HTML 子列表`

| 层次 | 当前项目定位线索 | 容易漏掉的部分 |
| --- | --- | --- |
| 产品表单 | `src/views/backend/content/product/popupForm.vue`、`productTabPurpose.js` | 新增默认值、编辑恢复、删除和排序、提交字段、Tab 用途说明 |
| 组件标签与字段契约 | `app/common/enum/ComponentTag.php`、`ProductService::buildProductScenarioCanonicalFields`，搜索 `CanonicalFields` | 精确标签、可编辑字段白名单、禁止将预览内容作为产品默认值 |
| 产品保存 | `app/service/basic/ProductService.php` 的新增、编辑、`saveComponentFields` | 整表保存和组件字段保存都要使用相同语义与校验 |
| 业务条目规范化 | `productSuccessCaseContract.js`、`ProductSuccessCaseService.php` | 字段类型、链接模式切换、旧数据读取、仅提交应持久化的字段 |
| 前台接口 | `ApiService::normalizeProductRuntimeRows`、`resolveProductSuccessCases` | 字段上抬到详情响应、站点范围、资产解析、有效链接、空数组 |
| 资产与详情地址 | `FileReferenceService`、`SiteProfileService::resolveCaseRuntimeDetailLink` | 存储文件 ID 与展示 URL 不同；链接使用系统详情页解析规则 |

不要只增加一个 Tab 或修改组件 JSON。字段没有进入服务端白名单可能保存丢失；没有进入接口输出则前台仍为空。产品详情专用输出应限定接口范围，避免意外改变产品列表契约。

图片控件的草稿可能是 URL、对象或文件 ID；沿用已有规范化和文件解析链路。编辑接口返回 ID、前台接口返回 URL 可以是正确设计，不应为了让两者字符串相等而改坏文件存储。

重复项使用稳定的本地 key，避免删除或重排后有状态选择器串项；草稿 key 不写入业务数据。

### 旧字段、清空与数据源切换

- 分清“字段不存在”和“用户已保存空数组”。仅在约定的旧数据迁移条件下读取旧字段，不能把 `[]` 当作继续兜底的理由；同时核对历史 JSON 字符串 `'[]'` 的归一化。
- 移除独立 Tab、切回公共字段时，删除独立草稿、默认值和写入逻辑，同步组件字段契约、HTML、unit_json 与说明。
- 旧页面实例可能仍持有旧 HTML 和数据源配置。可以在接口保留旧输出名作为新字段的只读别名，也可以按实际部署策略同步实例；只修改组件源文件不能证明已保存实例更新。
- 兼容输出别名与合并旧存储是两件事。没有迁移要求时，不自动把历史独立内容写入公共字段，也不在公共字段清空后恢复它。

556 的实例：`product_detail.detail_application_scenarios` 作为兼容输出，值来自当前 `application_scenarios`；历史 `ext_json.detail_application_scenarios` 保留但不参与展示。新组件直接使用原字段。

## 3. 产品详情子列表的动态契约

使用 `existing_api`，组件记录挂 `cat:product` 及对应业务标签。当前应用场景为 `content:product:scenario`，成功案例为 `content:product:success-case`。`detail:case` 用于目标案例详情页，不是产品内成功案例展示组件的标签。

以应用场景为例，HTML 根节点指令中的 `detail` 配置为：

```json
{
  "path": "product_detail",
  "id_params": ["product_id", "id"],
  "id_key": "id",
  "record_path": "data.list.0",
  "sublists": [{"field": "application_scenarios", "path": "application_scenarios"}],
  "auto_hide": {"enabled": true, "fields": ["application_scenarios"]}
}
```

这是指令片段，需放入完整 `data-lethink-dynamic`，执行入口使用现有统一入口。配套对齐 `unit_json.data_source.default.item_field`、顶层数组字段、`detail.sublists[].field/path` 与 `data-component-items`。产品 ID 从详情上下文或地址取得，不写死站点或产品 ID。

组件显示配置和产品业务数据分开：区块标题可以留在组件设置；业务数组由产品 Tab 维护。默认数组为空，预览样例放在独立 `detail_default` 中，仅供组件库预览，不进入产品保存默认值。正式空数据使用 `auto_hide`，不要恢复样例。

保留原稿的布局、类名、Swiper 容器、分页节点和交互钩子。无跳转需求时去掉 `href` 及实际点击跳转逻辑，必要时保留原 `<a>` 结构以兼容 CSS；不要使用 `href="#"` 冒充无跳转。有链接时使用接口最终输出的 `link`，不让模板自行拼接目标 ID。

## 4. 手填内容与关联链接分离

“选择本站案例只取地址”可保存以下字段：

- `title / image / description`：用户输入的展示内容。
- `link_type`：如 `custom` 或 `case`。
- `case_id`：本站跳转目标的 ID。
- `link`：自定义链接。

提交时只持久化当前模式的有效目标字段：案例模式保存 ID 并清空自定义链接，自定义模式保存链接并清空 ID。选择器、回显和后端运行时都不得自动用案例中心内容覆盖手填字段。

案例模式优先保存 ID，运行时从当前站点详情页配置解析地址，避免在数据库固化某个站点的路由。候选查询与运行时解析都检查站点、状态和删除标记，不能仅依赖前端过滤。当前实现可复用 `CaseCenterService::filterPublishedIds` 和 `SiteProfileService::resolveCaseRuntimeDetailLink`；用户指定系统详情页时，不改用案例记录的自定义外链。

表单是否允许保存，与前台是否渲染条目分别制定。调整必填项时同步标签星号、前端校验、后端整表保存和组件字段保存，不只去掉 UI 的 `required`。不要把缺图、无描述、未选目标等展示过滤条件暗中变成保存限制；如需过滤不完整条目，说明保存成功后的展示行为。

567 本次只要求标题必填，其他字段允许空；现有前台会跳过展示内容不完整或链接无效的条目。这是本组件的约定，不是新组件的默认规则。目标被停用或删除时，保留手填内容，按约定隐藏或禁用链接，不删除用户输入。

## 5. 复用可搜索选择器，检查弹窗内浮层

先搜索系统已有同类用法。当前项目使用 `ba-input` 的 `remoteSelect`，源码位于 `src/components/baInput/components/remoteSelect.vue`，案例候选来自 `/basic.caseCenter/index`。复用时核对关键词参数、分页、初始 ID 回显、清空值及当前站点上下文；`filterable` 本身不证明已接通远程搜索。

远程搜索的关键行为：

- 每次输入都更新关键词，再由防抖调度请求；不能因正在防抖或加载而丢弃后续字符。
- 关键词变化重置页码，翻页保留关键词，清空恢复未筛选列表。
- 用请求序号或取消机制使旧响应失效，避免慢请求覆盖新结果；旧请求也不能关闭新请求的 loading。
- 每个选择器实例独立持有请求状态，复制每次请求的参数，防止多条案例共用分页和初始化值。

弹窗内的两个常见症状分别处理：

| 症状 | 原因与处理 |
| --- | --- |
| 下拉只显示一行、被截断 | 检查 Tab 和弹窗滚动容器的 overflow；允许浮层 teleport 到 body，并核对层级及滚动定位 |
| teleport 后“无数据”面板横向全屏 | 宽度百分比改为相对 body 计算；用触发控件的实际宽度约束浮层，必要时处理 min-width |

公共选择器可能同时包含原生选择浮层和自定义空态/分页 Popover，需分别检查挂载位置与宽度。现有实现使用 `useElementSize` 跟随控件宽度，适应弹窗最大化或布局变化；不要用固定像素宽度或全局放开 overflow 掩盖问题。若改到公共控件，回归其其他使用场景。

## 6. 针对改动验证并交付

优先验证会改变数据或用户行为的边界，按实际改动选取：

- 数据与保存：新增、回显、修改、删除、清空；两种保存入口；新字段为空时不回填旧数据；不相关产品字段保留；文件 ID 正确解析。
- 关联与校验：选择目标不覆盖手填内容，两种链接模式切换，当前站点有效目标与跨站/停用目标，调整后的必填规则在前后端一致。
- 浏览器交互：Tab 归属正确、删除重排不串项；连续输入、清空、无匹配、分页、慢响应及多个选择器独立工作；长标题、空态、弹窗滚动或最大化时浮层不截断也不撑满页面。
- 动态展示：真实详情响应驱动新配置与需兼容的旧配置，空数据隐藏，无链接卡片不可跳转，有链接卡片指向预期详情页。

运行 `validate-unit-json.mjs`。当前校验器对 `detail.sublists` 的字段识别可能产生提示；核对具体提示、真实指令和运行时 DOM，不盲目压掉警告，也不改成错误的顶层绑定来迎合校验器。

浏览器隔离加载真实表单并模拟候选接口可以验证交互，但不能证明真实查询或保存成功。真实保存可在本地测试数据库通过事务回滚验证；如果详情接口另开连接，它可能读不到未提交数据，先识别连接边界，不为测试改变正式数据库的隔离级别。分别报告静态校验、隔离交互、本地真实保存/接口与正式 CMS 页面验证的范围。

交付完整 HTML 与 unit_json，列明后台代码部署、组件标签、数据维护入口、页面实例同步和既有 CSS/JS 依赖。如果同时维护仓库交付目录和用户指定组件目录，确保两处产物一致，保留 `origin.html` / `origin.json` 原稿。组件源码、本地验证通过与正式资源录入发布是不同状态，不互相替代。
